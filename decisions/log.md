# decisions/log.md — OrderNook

- **11 Jul 2026 — Design mix:** Travo Purple for shop dashboard, Latte Glass as customer PWA default theme (per-shop branding overrides via `shops.branding` CSS variables). Reason: dashboard is a SaaS utility; customer side needs the warm food/drink feel and gets re-themed per tenant anyway.
- **11 Jul 2026 — Paused wez_me_van** on Supabase to free the second free-plan slot for the order-ahead project (Lloyd's explicit choice over local Docker or Pro upgrade).
- **11 Jul 2026 — No service-role key in the app.** All privileged operations are Postgres SECURITY DEFINER functions (`create_order`, `get_order_by_token`, `attach_push_subscription`) called over RPC with the publishable key. Server-side price validation lives in the DB, not in route handlers. Reason: Supabase MCP doesn't expose the service key, and DB-enforced validation is stronger than API-layer validation.
- **11 Jul 2026 — Guest order access = unguessable `access_token` uuid** on orders, exposed only through token-scoped functions; anon role has zero direct read access to orders (customer status page polls `get_order_by_token`).
- **11 Jul 2026 — Per-shop daily order numbers** computed under a `FOR UPDATE` lock on the shop row, day boundary in the shop country's timezone.
- **26 Jul 2026 — Product name = OrderNook** (replacing the "Order-Ahead" placeholder). Punchline: *"A cosy corner for every order."* Reason: keeps the warm "friend in business" feel Lloyd wanted; verified clear of existing products (app stores + web) and `ordernook.uk` available. Rejected: **OrderMate** (Lloyd's initial favourite — it's an established Australian hospitality POS brand, all domains taken), **OrderNest** (recommended then withdrawn — live "OrderNest – Restaurant POS" on both app stores + ordernest.com), **Orderly/Order Pro** (crowded/generic). Process lesson: check existing app-store products, not just domains, before recommending a name.
- **26 Jul 2026 — GitHub repo created:** private repo `Nselenduna/ordernook` (https://github.com/Nselenduna/ordernook); existing local `master` history pushed. Deployed earlier same day to Vercel project `lloydmgutshini-projects/order-ahead` (project not yet renamed to match).
- **26 Jul 2026 — Phase 1 approach = lean pilot-first.** Lloyd hand-onboards 2–3 pilot shops (seed script) rather than building self-serve registration first; Phase 1 sliced into Go-Live Kit → menu editor → branding → self-serve. Reason: fastest path to a live pilot, matches "learn by shipping". Self-serve registration deferred until a shop asks.
- **26 Jul 2026 — Slice 1 = Go-Live Kit** (spec: `phase1-go-live-kit.md`). Reuses existing Phase 0 backend (is_paused/is_available/prep_minutes already enforced by create_order; staff-update RLS already present) — mostly dashboard UI + one migration (`menu_items.allergens`) + client-side QR. Hours kept simple (accepting-orders toggle + prep time; no 7-day schedule). Payments stay Phase 2 (reuse BookOnTheMap's Connect/subscription scaffolding but with direct charges per SPEC, not destination charges).
